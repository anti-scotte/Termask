## 1. 定位与边界

TermAsk 是一个**桌面端知识整理工作台**：用户在浏览器里划词，词汇通过本地桥接进入工作台，由大模型把零散概念整理成**概念图谱**（节点 + 带关系词的连线 + 总结），也可以在白板上做自由梳理。

后端是唯一持有「**状态 + 凭证 + 磁盘**」的一层。前端不直接访问网络（除 Tauri 官方插件外都走命令），浏览器扩展不直接写磁盘。因此后端是三端契约的收敛点：所有字段命名、错误文案、落盘位置都在这里定型。

| 层 | 职责 | 本文档是否覆盖 |
| --- | --- | --- |
| 后端 `src-tauri/` | 本机桥接 HTTP 服务、LLM 三协议调用、50 个 Tauri 命令、JSON 数据落盘、导出渲染、账户与验证码、系统能力 | **是** |
| 前端 `src/` | React WebView 页面渲染、交互、状态管理；经 `invoke` 调后端命令 | 否，见前端项目介绍书 |
| 扩展 `extensions/term-ask/` | 浏览器划词、全文快照、批量模式；经 HTTP 推到桥接 | 否，属前端范围 |

> 边界说明：前端介绍书 §10 曾建议后端文档一并覆盖 `extensions/term-ask/`。该目录是浏览器插件（WXT / MV3，前端代码），其许可证亦归入 `LICENSE-frontend.md` 的前端范围，因此本文档不描述其内部实现，只描述它与后端之间的 HTTP 契约（§5）。这样可避免两份介绍书对同一份源码给出互相矛盾的表述。

一句话数据流：

```text
划词（浏览器扩展）
   → 本机 HTTP 桥接（127.0.0.1:17570，Axum）
      → 内存暂存区（CacheStore）
         → 前端工作台（Tauri WebView，invoke / 事件）
            → LLM（OpenAI 兼容 / Anthropic / Ollama）→ 图谱 / 总结 / 分类
               → 本地 JSON 落盘（按用户隔离）
```

## 2. 技术选型与理由

| 选择 | 理由 | 代价 |
| --- | --- | --- |
| Tauri v2（Rust + WebView） | 安装包小、可调系统能力（自启 / 快捷键 / 文件 / 更新） | 需处理 WebView 与 Tauri 的协议差异 |
| 本地 HTTP 桥接（Axum） | 浏览器扩展无法调用 Tauri IPC，只能走 HTTP | 需自己做安全边界（Origin / 令牌 / 限流） |
| 无数据库，JSON 文件 | 单机单用户、数据量小、便于备份迁移 | 并发写依赖原子写与目录隔离 |
| OpenAI 兼容协议 | 一套代码适配 DeepSeek / Gemini / Kimi / GLM / Ollama | 各家字段与端点差异需容错 |
| 手写 SHA-256 | 避免引入加密依赖 | 必须自行保证正确性，改动需回归「注册 → 重启 → 登录」 |
| 手写 ZIP（DOCX） | 避免 Office 重依赖 | ZIP 结构需严格符合规范 |
| lettre（纯 Rust TLS） | SMTP 真实投递需支持 STARTTLS / SSL，手写协议不安全 | 约 +20 个传递 crate；关闭默认特性，不引入系统 OpenSSL |

主要依赖（`src-tauri/Cargo.toml`）：`tauri 2`、`tokio 1`、`axum 0.8`、`tower-http 0.6`、`reqwest 0.12`、`serde 1` / `serde_json 1`、`printpdf 0.7`、`resvg 0.49`、`flate2 1`、`crc32fast 1`、`lettre 0.11`，以及 `tauri-plugin-opener / autostart / global-shortcut / updater 2.14.1 / dialog 2.8.4`。许可证见 LICENSE-backend.md §2。

## 3. 代码地图

```text
src-tauri/src/
├─ lib.rs        领域层：类型、LLM 单一入口、账户、存储、导出落盘、50 个 Tauri 命令、入口装配（约 3.6k 行）
├─ bridge.rs     协议层：11 条 Axum 路由 + 请求校验 + 事件广播（约 330 行）
├─ cache.rs      状态层：CacheStore 单例（graph / whiteboard / full_context / batch_mode）
├─ security.rs   安全层：Origin 白名单、令牌、限流、安全响应头
├─ classify.rs   概念分类：LLM 批量打标 + 启发式兜底 + 宽容解析
├─ export.rs     导出：layout() → render_svg() → HTML / PNG / PDF / DOCX / MD / JSON（约 780 行）
└─ main.rs       桌面入口（调用 lib.rs 的 run()）

src-tauri/capabilities/default.json   Tauri 能力声明（插件权限）
src-tauri/tauri.conf.json            窗口、CSP、bundle、plugins.updater
src-tauri/examples/export_demo.rs    导出冒烟工具（不依赖前端、不读用户数据）
```

| 文件 | 职责 | 不允许做的事 |
| --- | --- | --- |
| `lib.rs` | 领域数据、LLM、账户、文件存储、命令与装配 | 不直接建 Axum 路由 |
| `bridge.rs` | HTTP 协议转换、请求校验、事件广播 | 不写业务规则、不落盘 |
| `cache.rs` | 内存暂存区 | 不依赖 Tauri、不做 IO |
| `security.rs` | 安全边界 | 不依赖业务类型 |
| `classify.rs` | 分类与容错解析 | 不改图谱数据结构 |
| `export.rs` | 布局与六格式渲染 | 不读用户数据、不决定落盘位置 |

依赖方向：`bridge → cache/security`；`lib → 全部`；`classify/export` 只依赖 `lib` 的公开类型与 LLM 入口。

前端契约（**后端改动必须同步核对**）：`src/lib/bridge-ext.ts` 是新增命令的**契约权威源**，`src/types/index.ts` 为共享类型，`src/lib/bridge.ts` 对前者 re-export。

## 4. 六个必须理解的设计决策

1. **所有跨端结构体都是 camelCase**：`#[serde(rename_all = "camelCase")]` 漏写不会报错，只会让前端字段全部变成 `undefined`——这是本项目历史上最难查的一类 bug。新增结构体必须立刻检查。
2. **暂存区是单例，按 target 分区**：`CacheStore` 内部有 `graph` / `whiteboard` 两个列表（各上限 200，FIFO）、`full_context` 单槽位、`batch_mode` 开关。Tauri 托管状态按 `TypeId` 索引，同类型 `.manage()` 两次会 panic，因此不允许引入第二个 `Arc<Mutex<Vec<StagedWord>>>`。
3. **桥接只信任三类来源**：`security::guard` 依次做限流（600 次 / 10 秒）→ Origin 白名单 →（可选）令牌 → 安全响应头。网页来源一律 403；扩展协议、Tauri 协议、dev server 放行；令牌用于挡住本机伪造 Origin 的进程。
4. **LLM 调用只有一个入口**：`call_llm_text` / `call_llm_text_with_timeout`（`lib.rs`），三种协议 `openai-compatible` / `anthropic` / `ollama`；URL 拼接必须走 `openai_endpoint()`，扩展侧同规则的 `joinChatCompletions()` 两端必须同步。自由问答命令 `ask_llm` 只增加采样参数（temperature 0.3、max_tokens 4096、超时 120s），未新增 HTTP 逻辑。
5. **模型输出一律「能救则救」**：图谱 JSON 多字段名兜底解析；空连线由 `ensure_edges` 按顺序自动串联；分类解析或调用失败整批降级启发式并返回 `degraded=true`；白板批注模型回纯文本时当正文用。这是针对「免费 / 低价模型输出不稳定」的产品级防御，不应改回严格解析。
6. **导出：一次布局，多载体**：`layout()` 算坐标 → `render_svg()` 是唯一图形渲染器 → HTML 内联、PNG 光栅化；PDF / DOCX 是排版文档，走各自的文本流。新增格式只需加一个 `render_bytes` 分支。前端渲染产物（白板 PNG / SVG 等）则走通用命令 `write_export_file` 落盘，后端不参与渲染。

## 5. 桥接服务：11 条路由与事件

| 方法 | 路由 | 用途 |
| --- | --- | --- |
| GET | `/health` | 探活 |
| GET | `/api/bridge-info` | 桥接信息 |
| POST | `/api/concept-graph` | 扩展推送概念图（覆盖画布） |
| POST | `/api/add-to-graph` | 词条进概念区 / 全文快照 |
| GET | `/api/get-cache-count` | 暂存区计数 |
| GET | `/api/staged-words` | 概念收集区词条 |
| GET | `/api/whiteboard-words` | 白板收集区词条 |
| POST | `/api/remove-last` / `/api/remove-word` / `/api/clear-cache` | 撤销 / 指定删除 / 清空 |
| GET / POST | `/api/batch-mode` | 批量划词开关 |

请求体上限 2 MiB；解析失败按 `JsonRejection::status()` 返回 413 / 422，不再一律 422。

桥接事件（`emit` 必须在前端找到对应 `listen`，否则是死契约）：`staged-word`、`whiteboard-word`、`full-context`、`staged-word-removed`、`concept-graph`、`trigger-shortcut`。

> 命令数口径以 `docs/8-后端工程状态-2026-11-05.md` §4 为准（当前 50 个）。前端项目介绍书 §10 写的「28+ invoke 命令」是早期批次口径，两者不一致时以状态文档为准。

契约约定：命令名用蛇形、前端 `invoke` 同名；入参统一放一个对象；返回结构体或 `Result<T, String>`；错误信息直接面向用户、中文、不含英文堆栈。任何新增命令必须注册进 `generate_handler!`；任何新增桥接路由必须加入 `bridge.rs` 的 `ROUTES` 常量。

代表性出参：`export_graph_project` / `write_export_file` → `{ path, format, bytes }`；`check_app_update` → `{ available, currentVersion, latestVersion?, notes? }`；`get_smtp_config` → `{ enabled, server, port, username, fromName, encryption, hasPassword, mockMode }`（授权码恒不回显）；`get_global_shortcut` → 当前生效键字符串，偏好缺失回退 `Ctrl+Shift+Q`，**永不返回空串**。

## 7. 数据与存储布局

```text
<数据根目录>/                     # 默认 %APPDATA%/com.sysfr.termask-workbench
├─ location.json                  # ⚠ 指针文件留在【系统默认目录】，不在数据根目录内
├─ bridge.json                    # 桥接令牌 + requireToken（本机安全配置，不随迁移）
├─ smtp.json                      # SMTP 配置 + 授权码（本机安全配置，不随迁移）
├─ preferences.json               # autoClassify / globalShortcut
├─ session.json                   # 登录会话（重启恢复）
├─ settings.json                  # 游客设置（前端 JSON 透传）
├─ graphs/  whiteboards/  exports/
└─ users/{user_id}/
   ├─ account.json                # 盐 + 10000 轮 SHA-256
   ├─ settings.json
   └─ graphs/  whiteboards/  exports/
```

落盘约定：

1. 一项目一文件，文件名 = `id.json`；`id` 必须过 `is_safe_id`（挡 `..`、`/`、`\`）；
2. 写 `.tmp` 再 `rename`，避免崩溃留下半截文件；
3. 目录按登录态隔离，登录用户 `users/{user_id}/...`，游客走根目录；
4. 数据根目录可由用户在设置中迁移：**只允许写入空目录**，复制成功后才切换指针；指针文件永远留在系统默认目录，目标盘掉线不会让应用起不来；`bridge.json` / `smtp.json` 复制时被显式跳过。

内存态（`CacheStore`，进程级单例，重启即丢）：`graph` / `whiteboard` 两个列表（上限 200，FIFO）、`full_context` 覆盖式单槽位、`batch_mode` 开关。

## 8. 导出渲染管线

| 格式 | 实现 | 依赖 | 备注 |
| --- | --- | --- | --- |
| HTML | 自包含（内联 SVG + 样式） | 无 | 可直接分享 / 打印 |
| PNG | SVG → `resvg` 光栅化 | `resvg` | 2 倍缩放，宽度上限 2400px |
| PDF | `printpdf` + 系统 TTF 子集嵌入 | `printpdf` | 需 TTF；微软雅黑是 `.ttc` 不可用，会回退 `simhei` / `simkai` / `Deng` |
| DOCX | 手写 ZIP + WordprocessingML | `flate2` / `crc32fast` | 无 Office 依赖；表格 + 标题 + 列表 |
| Markdown / JSON | 直接序列化 | 无 | 文本备份 |

PDF 单测断言 `/FontFile2`（字体已嵌入）与 `Identity-H`（CID 编码），缺一即中文空白。字体随用户操作系统分发，其授权不在本项目范围内。

两条落盘路径共用原子写：

- `export_graph_project(project, format, fileName?)`：后端渲染 `render_bytes` 后落盘，六格式；
- `write_export_file(fileName, base64Content)`：接收前端已渲染的 base64 字节（白板 PNG / SVG、Canvas blob），**不参与渲染**；`fileName` 过 `is_safe_id`，扩展名白名单 `png / svg / html / json / md / pdf / docx / markdown`，base64 手写解码，字符串上限 64 MiB。

`export_demo` 冒烟工具支持可选图谱 JSON 路径；路径不存在或解析失败自动回退内置示例图谱，并输出 `sample-graph.json` 快照供复跑，形成「无图谱也能测 + 有图谱可复跑」的闭环。

## 9. 账户、验证码与系统能力

| 项 | 现状 |
| --- | --- |
| 密码策略 | 8–64 位，至少一个字母 + 一个数字（注册与改密共用 `validate_password`） |
| 密码存储 | 盐 + 10000 轮 SHA-256（手写实现） |
| 登录限流 | 同账号连续 5 次失败 → 锁定 60 秒（内存态） |
| 账号枚举 | 未注册与密码错误统一返回「账号或密码不正确」 |
| 验证码 | 有效期 `CODE_TTL_SECS = 300`（5 分钟），一次性、连错 5 次作废 |
| 邮件通道 | 配置驱动：`enabled=true` 且配置完整且账号为邮箱 → SMTP 真实投递（20s 超时，`starttls` / `ssl` / `none`）→ `devCode=null`；未配置、手机号账号、投递失败或超时 → 回退 MOCK 备用模式（`devCode` 回传前端） |
| 配置存储 | `<系统默认数据目录>/smtp.json`，`.tmp` → `rename`；授权码不进代码、日志、文档；`get_smtp_config` 脱敏；`password` 留空表示保留原授权码 |

系统能力：`tauri-plugin-autostart`（开机自启动）、`tauri-plugin-global-shortcut`（默认 `Ctrl+Shift+Q`，`set_global_shortcut` 成功即写 `preferences.json`，失败回滚默认键并写盘，`setup` 启动时按偏好注册）、`tauri-plugin-dialog`（目录选择）、`tauri-plugin-opener`、`tauri-plugin-updater`（检查 / 安装更新命令，能力 `updater:default`）。

**自动更新的启用条件（缺一不可）**：① `tauri.conf.json` 配置 `plugins.updater.endpoints` 与 `pubkey`；② 发布机设置 `TAURI_SIGNING_PRIVATE_KEY` 且 `bundle.createUpdaterArtifacts = true`；③ 清单里的 `version` 大于当前版本。v0.1.0 三项均未提供，因此命令返回可读中文提示而不阻断应用启动——这是刻意设计，不编造清单 URL 或签名公钥。

## 10. 开发、验证与常见任务

```bash
# 启动（含 Vite）
npm run tauri dev

# 后端编译（不与 dev 抢 target 锁）
cd src-tauri && CARGO_TARGET_DIR=target-check CARGO_INCREMENTAL=0 cargo check --message-format=short

# 后端单测
CARGO_TARGET_DIR=target-check CARGO_INCREMENTAL=0 cargo test --lib

# 导出冒烟
CARGO_TARGET_DIR=target-check cargo run --example export_demo -- target-check/export-sample

# 前端类型（改过跨端契约就跑）
cd .. && npx tsc --noEmit

# 桥接探活
curl http://127.0.0.1:17570/health
curl http://127.0.0.1:17570/api/bridge-info
```

判定「后端改动完成」的最小标准：**`cargo check` 零警告 + `cargo test` 全绿 + 应用能启动 + 改动的命令有一次真实调用**。

v0.1.0 实测：`cargo check` 0 error / 0 warning；`cargo test --lib` 24 passed（cache 4、security 2、classify 3、export 6、command_tests 9）；`npx tsc --noEmit` 通过；六格式导出产物齐全。**未验证**：应用启动、命令真实调用、真实邮件投递、快捷键运行时注册与重启恢复。

| 任务 | 落点 | 注意 |
| --- | --- | --- |
| 新增 Tauri 命令 | `lib.rs` → `generate_handler!` | 结构体加 camelCase；错误用中文 |
| 新增桥接路由 | `bridge.rs` 的 router | 自动继承安全层；同步更新 `ROUTES` 常量 |
| 新增 LLM 供应商 | `call_llm_text_inner` 的 match | 同时更新 `openai_endpoint` 兼容性测试 |
| 调整分类类型 | `classify.rs` 的 `KINDS` + 前端 `CONCEPT_KINDS` | 两端必须同步 |
| 新增导出格式 | `export.rs` 的 `ExportFormat` + `render_bytes` | 加扩展名与单测 |
| 改账户策略 | `validate_password` / `login_account` | 改哈希必须回归「注册 → 重启 → 登录」 |
| 改数据目录结构 | `app_root()` 与各 `*_dir` | 兼容旧数据，不直接换路径 |

协作纪律：前后端可能被不同会话并行修改；**禁止整文件覆盖写**（先 Read 最新内容再精确替换）；不执行删除命令（迁移只做复制 + 指针切换）；不擅自杀进程（`os error 5` 用 `CARGO_TARGET_DIR` 绕开）；改动后同步 `docs/8`。

3. 导出回归：`export_demo` 六格式产物齐全，PDF 含字体子集。
4. 真机回归：启动应用，对改动命令各做一次真实调用（docs/9 §6 最小标准）。

### 11.3 双平台发布
